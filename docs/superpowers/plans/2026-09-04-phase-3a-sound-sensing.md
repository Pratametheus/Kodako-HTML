# Fase 3a — Suara + Sensor lengkap: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sprite mode gains the two block categories that make real little games possible: **Suara** (play / play-until-done / stop-all / volume, with ~8 bundled CC0-style sound effects) and **full Sensor** (`menyentuh tepi/sprite/pointer?`, `menyentuh warna?`, `mouse ditekan?`, `posisi x/y mouse`, `jarak ke`, `tanya … dan tunggu` + `jawaban`). Everything runs through the existing synchronous-ES5 generator + JS-Interpreter + per-frame scheduler with no regressions.

**Architecture:** New Suara/Sensor block JSON + generator handlers emit bare-global calls exactly like Phase 1 (`playSound(...)`, `isTouching(...)`, sync; `playSoundUntilDone(...)`, `ask(...)`, async duration requests). `src/runtime/sprite/audio.ts` (new) is a Web Audio wrapper (decode+cache `AudioBuffer`, play/stop-all, per-sprite gain). `RuntimeContext` grows a `mouse` position/pressed record, a shared `answer` string, and an audio-engine handle. The scheduler learns two new `DurationRequest` kinds: `playUntilDone` (park until the audio source ends) and `ask` (park until the stage's answer box is submitted). `stage.ts` tracks mouse coords, samples pixels for `menyentuh warna?`, and renders the ask input box. All wired in `sprite-mode.ts`.

**Tech Stack:** Web Audio API (no library), Canvas 2D `getImageData` for colour collision, Blockly + JS-Interpreter (already in), Vite 6, TypeScript strict, Vitest/jsdom, Playwright. No new npm deps. All sound assets are files in the repo, generated by a committed script.

**Spec:** `docs/Design.md` §4.3 (the "Suara penuh" + "Sensor penuh" note), §6.3 (`api.ts` sensor list), §6.7 (`audio.ts` — Web Audio wrapper), §6.5 (stage renderer / hit-test); `docs/ROADMAP.md` → "Fase 3 — Poles & paket desktop" (the Suara + Sensor deliverables).

## Global Constraints

Every task's requirements implicitly include this section.

1. **Bahasa Indonesia** for every user-facing string incl. block captions (inline `message0`) and the ask-box placeholder/button. New UI strings → `src/app/i18n/id.json` via `t()`. Dev-console strings exempt.
2. **No third-party runtime network calls / no CDN, no new npm deps.** Sound effects are `.wav` files committed under `src/runtime/sprite/assets/sounds/`, produced by `scripts/gen-sounds.mjs` (committed) — the script writes deterministic PCM WAV bytes (sine/square/triangle/noise + linear envelope), no external input.
3. **JS-Interpreter is ES5** (established Phase 1 constraint): generator emits SYNCHRONOUS ES5. New sync ops (`playSound`, `stopAllSounds`, `changeVolume`, `setVolume`, `isTouching`, `isTouchingColor`, `isMouseDown`, `mouseX`, `mouseY`, `distanceTo`, `answer`) are plain sync native functions. New duration ops (`playSoundUntilDone`, `ask`) are `interpreter.createAsyncFunction` natives the scheduler resumes. No async/await/arrow/let/const/template-literals in generated code strings.
4. **TypeScript strict** (`noUncheckedIndexedAccess`, `verbatimModuleSyntax`); `import type` / inline `type`; **no `any` in product code**. `npm run typecheck` passes.
5. **Audio must not break jsdom tests.** `audio.ts` guards on `typeof AudioContext !== 'undefined' && ...` (also `webkitAudioContext`); when unavailable it returns a no-op engine (all methods present, `playUntilDone` resolves immediately). Unit tests inject a fake engine; jsdom never constructs a real `AudioContext`.
6. **No regressions.** The 251 existing unit + 4 E2E stay green. Phase 1's `forever`-doesn't-freeze guarantee, block highlighting, Stop responsiveness, and multi-sprite behaviour are untouched. `menyentuh warna?` pixel sampling must be O(sprite-bbox) per call and must not stall a frame.
7. **Conventional Commits**, one focused commit per task's final step. `.gitattributes` enforces `eol=lf`; `npm run format` before commit if needed. `git add` every new file; `git status --porcelain` clean before a task is "done".
8. **Deferred to 3b/3c (do NOT build here):** full Scratch block theme, polished/real art, error boundary, a11y pass, perf pass, Tauri build, CI release, Help page. HTML mode is untouched.

## Block set added by this phase

**Suara** (category colour: pink `#CF63CF`, style key `sound_*`)
- `mainkan suara [kucing ▾]` — fire-and-forget → `playSound(<id>);`
- `mainkan suara [kucing ▾] sampai selesai` — → `playSoundUntilDone(<id>);` (async)
- `hentikan semua suara` → `stopAllSounds();`
- `ubah volume [-10]` → `changeVolume(-10);`
- `atur volume ke [100] %` → `setVolume(100);`

`suara ▾` dropdown: dynamic, backed by the sprite's `sounds` list; default `[['(tidak ada suara)','']]`. Set via `setSoundOptionsProvider`.

**Sensor** (existing category `sensing_*`, light-blue — add to it)
- `menyentuh [tepi ▾]?` — dropdown `tepi` / `pointer mouse` / one entry per other sprite name → `isTouching(<target>)` boolean
- `menyentuh warna [#e53935 ▾]?` — colour dropdown (reuse Phase 1 palette or a `field_colour`) → `isTouchingColor(<hex>)` boolean
- `mouse ditekan?` → `isMouseDown()` boolean
- `posisi x mouse` → `mouseX()` number
- `posisi y mouse` → `mouseY()` number
- `jarak ke [pointer mouse ▾]` — dropdown `pointer mouse` + other sprite names → `distanceTo(<target>)` number
- `tanya [Siapa namamu?] dan tunggu` → `ask(<text>);` (async command)
- `jawaban` → `answer()` string reporter

Existing Phase-1 Sensor blocks (`tombol [k] ditekan?`, `pengatur waktu`, `reset pengatur waktu`) stay.
